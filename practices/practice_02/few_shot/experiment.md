# Few-shot

- Артефакт Практики 1: `tests_e2e.md`
- Что хотим улучшить: сделать ожидаемые результаты однозначными по OUT-1 и зафиксировать граничный случай `len(diff) == 20000` как валидный (413 — только при `> 20000`).

## Примеры

### Хороший результат

Ответ содержит JSON со строгими полями OUT-1:

```
{
  "summary": "…",
  "risks": [
    {"file": "app/review_service.py", "line": 16, "evidence": "…", "risk": "…"}
  ],
  "checks": ["…", "…"]
}
```

Пояснение: структура проверяема и не зависит от интерпретации «полезности».

Ещё один хороший пример (граничный случай):

```
len(diff) == 20000 → HTTP 200; LLM вызывается; ответ соответствует OUT-1.
```

### Плохой результат

Ответ «должен быть полезным для ревьюера и содержать рекомендации по улучшению кода».

Проблема: непроверяемо и не привязано к OUT-1; не ясно, какие поля обязательны.

## Запрос

Используй только `TRAINING_PR.diff` и `context.md` (раздел OUT-1). Улучи `tests_e2e.md` так, чтобы:
1) позитивный сценарий требовал точные поля `summary`, `risks` (≤3, с `file,line,evidence,risk`), `checks`;
2) явно зафиксировать, что `len(diff) == 20000` — валиден, а 413 возвращается только при `len(diff) > 20000`.

Верни краткий diff-план правок и пример ожидаемого ответа.

## Что получили

- План правок:
  - В позитивном сценарии указать поля OUT-1 явно и запретить лишние поля.
  - Добавить отдельный граничный сценарий `len(diff) == 20000` → 200 OK, LLM вызывается.
  - Уточнить негативный сценарий: 413 только при `> 20000`.
- Пример ожидаемого ответа добавлен (см. «Хороший результат» выше).

## Что изменили в исходном артефакте

- Файл и раздел: `practices/practice_01/tests_e2e.md` — таблица сценариев
- Изменение: уточнён формат позитивного ответа по OUT-1 и добавлен отдельный сценарий для `len(diff) == 20000`
- Как проверили: сопоставили с Context Pack (`OUT-1`, `API-1`) и подтверждёнными строками из `TRAINING_PR.diff`
- Что отклонили: «полезность ответа», auth, rate limiting — вне scope и непроверяемы в E2E на этой практике
