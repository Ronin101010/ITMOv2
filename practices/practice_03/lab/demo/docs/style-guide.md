# Style Guide (Notify Mini)

Правила для маленьких изменений A/B
- Проверяй поведение через публичный интерфейс (`subscribe`). Не обращайся к внутреннему состоянию напрямую вне тестов.
- Используй явные ошибки для неверного ввода. Не вызывай LLM при отклонении входа.
- Не добавляй новые фреймворки/зависимости без необходимости.
- Не ослабляй runner ради зелёного результата; фиксируй причину.
- Поддерживай idempotency: повторные подписки не создают дубликаты.

Пример
- Для пустого имени: тест падает, затем `subscribe` поднимает `ValueError("empty name")` и проверка проходит.
